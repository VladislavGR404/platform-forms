# Лог работы с AI-ассистентом
## Проект: «Конструктор форм отклика» (MVP карьерной платформы)

**Стек:** Node.js, Express, SQLite, Bootstrap 5, marked.js, multer.
**Репозиторий:** публичный, GitHub. Запуск: `npm install` → `npm start` (порт из переменной окружения PORT, по умолчанию 3000).

Ниже приведена последовательность итераций разработки: запрос → результат.


---

### Итерация 1. Планирование MVP по ТЗ

**Запрос:** Вот такое ТЗ, его надо сделать — веди меня по шагам.

**Результат:** Сформирован план: стек Node.js + Express + SQLite, Bootstrap; схема БД из двух таблиц (forms, submissions); маршруты админки (/admin, /admin/create), публичной формы (/form/:id) и API; критерии приёмки (npm install / npm start, порт из переменной окружения).


---

### Итерация 2. Базовый сервер и админка

**Запрос:** Реализовать сервер с маршрутами: список форм, конструктор, публичная форма, отправка ответов.

**Результат:** server.js: редирект с '/' на '/admin'; GET /api/forms; POST /api/forms (генерация uuid, сохранение полей JSON); GET /api/form/:id; GET /form/:id; POST /api/form/:id (multer.any()). Исправлена ошибка Cannot GET / — добавлен редирект на /admin.


---

### Итерация 3. Типы полей и валидация

**Запрос:** Сделай отдельное поле для Email, которое проверяется браузером, а для числового — проверку с min/max.

**Результат:** В конструктор добавлены типы полей: text, email, number, textarea, file, checkbox. Для email генерируется <input type="email"> (встроенная HTML5-валидация). Для number — инпуты «Мин/Макс» в конструкторе, значения сохраняются в конфигурации поля и выводятся как атрибуты min/max на публичной форме.


---

### Итерация 4. Ограничение загрузки файлов 3 МБ

**Запрос:** Ограничить размер загружаемых файлов 3 МБ на клиенте и сервере.

**Результат:** server.js: multer limits { fileSize: 3*1024*1024 } + middleware-обработчик ошибок (LIMIT_FILE_SIZE → понятный JSON-ответ). form.html: клиентская проверка размера перед отправкой с alert по имени поля.


---

### Итерация 5. Фильтрация расширений файлов

**Запрос:** Нужно, чтобы грузились только документы (PDF, DOC, DOCX, TXT, RTF) — исполняемые файлы блокировать.

**Результат:** Двухуровневая проверка: на клиенте — атрибут accept и проверка расширения перед отправкой; на сервере — валидация расширения по настройкам конкретного поля (fieldConfig.allowedExtensions), запрещённый файл удаляется и запрос отклоняется с 400. В конструкторе добавлен выбор разрешённых форматов чекбоксами (PDF/DOC/DOCX/TXT/RTF).


---

### Итерация 6. Удаление форм с подтверждением

**Запрос:** Добавить удаление формы через админку с диалогом подтверждения.

**Результат:** API: DELETE /api/forms/:id — сначала удаляются ответы (submissions), затем сама форма; защита от «висячих» записей. admin.html: кнопка «Удалить» + confirm() с предупреждением об удалении ответов.


---

### Итерация 7. Просмотр ответов и человекочитаемые названия полей

**Запрос:** Смотри, в ответах на форму названия полей некорректные  вместо ID покажи нормальные названия.

**Результат:** Эндпоинт GET /api/forms/:id/submissions доработан: перед выдачей ответов строится маппинг id → label из конфигурации формы, ключи answers заменяются на label. admin.html: модальное окно со списком откликов; файлы отображаются как кликабельные ссылки «Скачать файл».


---

### Итерация 8. Редактирование форм

**Запрос:** Добавь, чтобы я мог вернуться в редактор уже созданной формы.

**Результат:** Маршрут GET /admin/edit/:id (отдаёт create.html). POST /api/forms доработан: при наличии id в теле выполняется UPDATE вместо INSERT. create.html: при открытии по /edit/:id загружаются title, описание и поля формы; кнопка меняется на «Сохранить изменения». Исправлена ошибка Cannot GET /admin/edit (маршрут был размещён после app.listen — перенесён выше).


---

### Итерация 9. Описание формы с поддержкой Markdown

**Запрос:** Давай добавим менеджеру поле описания формы с форматированием Markdown и сразу готовым предпросмотром.

**Результат:** В БД добавлена колонка description (миграция: ALTER TABLE, при ошибке — пересоздание БД). Подключена библиотека marked.js с CDN. create.html: тулбар (жирный, курсив, ссылка, список) и live-режим — при потере фокуса textarea скрывается и показывается отрендеренный HTML, клик возвращает редактор. form.html: описание рендерится через marked.parse(). Исправлен toggle-форматирования: повторное нажатие снимает ** и * вместо добавления новых.


---

### Итерация 10. Аналитика отвалов (Drop-off Analytics)

**Запрос:** Реализуй сбор статистики: на каком поле студенты бросают заполнение формы.

**Результат:** Таблица dropoffs (form_id, field_id, created_at, каскадное удаление). form.html: трекинг последнего активного поля (focus/input), отправка фоновым запросом navigator.sendBeacon при закрытии вкладки (visibilitychange), флаг formSubmittedSuccessfully исключает отправку после успешной отправки формы. API: POST /api/form/:id/dropoff, GET /api/forms/:id/analytics (конверсия, карта отвалов). admin.html: кнопка «Воронка», дашборд с метриками (просмотры/завершения/конверсия) и прогресс-барами отвалов по полям.


---

### Итерация 11. Прогресс-бар заполнения

**Запрос:** Хочу индикатор прогресса заполнения обязательных полей на публичной форме — давай реализуем.

**Результат:** form.html: блок прогресса над формой; функция updateProgressBar() считает заполненные обязательные поля (учитываются чекбоксы и файлы), цвет полосы меняется от жёлтого к зелёному при приближении к 100%; слушатели input/change на всех полях, инициализация после рендера полей.


---

### Итерация 12. Копирование ссылки на форму

**Запрос:** Добавь в админке кнопку копирования публичной ссылки в буфер обмена.

**Результат:** admin.html: рядом со ссылкой кнопка «Копировать» (navigator.clipboard.writeText), при успехе текст меняется на «Скопировано!» с возвратом через 2 секунды. Ссылка формируется полная: window.location.origin + /form/:id.


---

### Итерация 13. Тестовое наполнение базы (seed.js)

**Запрос:** А ты можешь создать заполненную базу, чтобы я мог потестировать? Пусть будет несколько форм и множество ответов.

**Результат:** Создан seed.js: создаёт таблицы (forms, submissions, dropoffs) самостоятельно, очищает старые данные и наполняет БД двумя формами («Стажировка Frontend Developer», «Летняя школа UI/UX Дизайна»), 9 ответами студентов и статистикой отвалов по полям. Запуск: node seed.js → npm start.


---

### Итерация 14. Отладка и стабилизация

**Запрос:** По ходу работы вылезли ошибки — помоги устранить.

**Результат:** Исправлены: Cannot GET / (редирект на /admin); Cannot GET /admin/create и /admin/edit/:id (добавлены маршруты sendFile); SQLITE_ERROR: no such column: description (миграция схемы); SQLITE_CONSTRAINT: FOREIGN KEY constraint failed при сидинге (таблицы создаются внутри seed.js до вставки данных); маршруты аналитики перенесены выше app.listen; повторное добавление **/* при повторном клике кнопок форматирования.


---

### Итог
Реализовано полноценное MVP: конструктор форм с типами полей и валидацией, загрузка файлов с ограничениями (3 МБ, белый список расширений), просмотр и удаление ответов, редактирование форм, Markdown-описания, аналитика отвалов по полям (воронка конверсии), прогресс-бар заполнения, тестовое наполнение базы. Проект опубликован на GitHub и запускается «из коробки».
